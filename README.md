# iOS Git Hooks

团队统一的 Git pre-commit 钩子，自动检查代码格式和敏感词。

## 一键安装

```bash
curl -fsSL https://raw.githubusercontent.com/BaiTu-iOS/ios-git-hooks/main/install.sh | sh
```

同一条命令也用于**更新**。

## 功能

| 检查项 | 说明 |
|--------|------|
| OC 格式检查 | `clang-format → xcindent` 组合校验，仅检查 `BT*.h/m/mm/cpp` 改动行；缩进对齐 Xcode Ctrl+I |
| Swift 格式检查 | 基于 swiftformat，检查暂存的 `.swift` 文件 |
| 敏感词检查 | compound 语义匹配，支持驼峰/下划线复合词边界识别 |

### 敏感词匹配示例

| 关键词 | 命中 | 不命中 |
|--------|------|--------|
| `pay` | `payType`, `pay_type`, `wx_pay` | `payload`, `display`, `repay` |
| `win` | `winCoin`, `win_coin`, `bigwin` | `window`, `darwin` |
| `money` | `moneyType`, `money_amount` | — |
| `bet` | `betAmount` | `beta`, `alphabet` |

## 依赖

- git 2.9+（支持 `core.hooksPath`）
- python3
- clang-format（通过 Xcode 自带 `xcrun --find clang-format`）
- [swiftformat](https://github.com/nicklockwood/SwiftFormat)（需自行安装: `brew install swiftformat`）

## 卸载

```bash
git config --global --unset core.hooksPath && rm -rf ~/.local/bin/git_hooks
```

## 维护

> ⚠️ **下面四个文件是生成产物，改了会被覆盖、且 CI 会拦**：
> `config/clang-format-config`、`config/vswiftformatconfig`、
> `hooks/xcindent.py`、`hooks/check_blocked_words.py`。
> 它们的头部都带 `AUTO-GENERATED BY workshop` 标记。

规则的唯一事实源在 **`BaiTu-iOS/workshop`**。改规则的流程：

1. 改 workshop 里的源文件（见下表）
2. 发对应 plugin 的 tag
3. workshop 的 `sync-git-hooks` workflow 自动同步回本仓库并 bump 版本号
4. 成员经 WuKong 拉取（24h 节流；紧急时 `git -C ~/.local/bin/git_hooks pull`）

| 要改什么 | 改 workshop 的哪个文件 | 发哪个 tag |
|---|---|---|
| OC 格式规则 | `plugins/ios-dev-rules/rules/objectivec/.clang-format` | `ios-dev-rules-v*` |
| Swift 格式规则 | `plugins/ios-dev-rules/rules/swift/.swiftformat` | `ios-dev-rules-v*` |
| 缩进引擎 | `plugins/wk-xcindent/scripts/xcindent.py` | `wk-xcindent-v*` |
| 敏感词 / 白名单 | `plugins/ios-blocked-words-check/skills/ios-blocked-words-check/scripts/check_blocked_words.py` 的 `BLOCKED_WORDS` / `COMPOUND_WHITELIST` | `ios-blocked-words-check-v*` |

本仓库自己维护的是**门禁编排层**（`hooks/pre-commit`、`ocformat`、`vswiftformat`、`check-sensitive-words`、`install.sh`），这些不是生成物，正常提交即可。

### OC 门禁的两级管线

先让 clang-format 处理空格、大括号和指针位置，再由 `hooks/xcindent.py`
对同一批改动行做缩进收尾。后者只改行首空白，用于解决尾随消息 block body
被 clang-format 推到参数列深缩进的问题。引擎源自 `wk-xcindent`，已通过
36 个真实 Xcode 26.6 oracle golden 用例校准。

检查过程完全在内存中完成，只输出建议 diff，不会直接修改工作区文件。
